# Ruby provider execution and ownership cases

These are original synthetic fixtures for reviewing Cucumber-Ruby provider glue. The parity checker executes these groups through `../provider-context-cases.json`, the single source of desired outcomes. They do not copy third-party source.

`lifecycle-direct` is the supported control: provider-loaded direct step definitions remain trusted around top-level `Before`, `Around`, and `After` callbacks; callbacks are not step definitions; equivalent handlers produce a duplicate-handler finding; a polarity-changing handler remains absent.

`callback-nested-registration` is the conservative uncertainty control: a `Given` nested inside a `Before` callback is not proven to register at suite-load time. It must not be counted or create findings; independent direct definitions retain their duplicate-handler finding, while strict completeness fails.

`unrelated-module-alias`, `uninstalled-module-given`, `world-module-given`, and `local-method-added` are ownership controls: none changes Cucumber's top-level registration receiver, so direct registrations should remain trusted and retain the duplicate-handler finding. Cucumber-Ruby 9.2.1 source says top-level DSL methods come from `extend(Cucumber::Glue::Dsl)`, while `World` modules are extended onto each scenario's World object; this separates load-time registration ownership from handler-time method lookup. The hiera-eyaml Gemfile allows Cucumber `~> 9.2` but has no lockfile, and its configured static roots do not include Cucumber itself, so the v9.2.1 source is a behavioral reference, not a pinned dependency closure.

`object-kernel-mixins` defines replacement DSL methods itself, so it must remain incomplete with no trusted registrations; a framework namespace spelling is not trusted provenance. `callback-nested-registration` keeps a nested `Given` uncertain while preserving the direct positive control. `global-method-added` is deliberately a strict-incomplete case: a global `Module#method_added` hook dynamically rewrites the Cucumber DSL registrar, and unsupported callback effects must not become trusted definitions. The exact point at which such a global hook affects a selected suite remains an execution-order boundary for the analyzer.

`receiver-local-send` distinguishes a statically constructed local receiver with its own `Given` method from the global Cucumber DSL; constructor and method-effect resolution remains an open requirement. A receiver whose identity/provenance is unknown remains incomplete and must not grant registration trust. The checker enforces preservation for proven unrelated declaration owners; an unknown external provider or dynamic receiver still needs its source boundary and effect modeled or reported incomplete.
